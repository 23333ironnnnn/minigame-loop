# 下注：规则和卡片

规则在这里（跟着 skill 升级）；账本在项目的 `docs/loop/bets.md`。

## 什么时候要下注

新玩法、改核心手感、改首页 / 主流程、改分享 / 积分 / 排行规则、新游戏上线。bug、文案、参数微调不用。

## 下注卡（复制这一块，编号接着往下排，不复用）

```markdown
### B-<编号> <一句话>（<开卡日期>，<版本 / PRD 条目>）
- 状态：待发 / 已发待结（<发版日期>）/ 已结
- 改了什么：<用户看得到的一句话>
- 主指标：<北极星里的哪一个；看板哪一块哪一行 / 平台后台哪个数>；口径：<哪些平台、新老用户、去不去机器人>
- 现在：<值>（<日期范围>）
- 预计：<区间>；结算日：<日期>
- 护栏：<不能变差的指标，比如做完率、报错率>
- 算判断错：<什么结果算错，比如主指标低于区间下沿、或护栏变差超过 2 个百分点>
- 依据：<memory.md 的 M-编号 / 参考图 / 用户原话>
- 结算：<日期> <实际值> → 中 / 没中 / 看不出；原因；记忆怎么改（M-编号 升 / 降 / 失效 / 新增）
```

## 写卡和结算的规矩

- 主指标只从 `project.md` 的北极星里挑；护栏另选，一张卡一到两个。
- 「现在」取发版前同样长的一段（一般 7 天），和结算窗口一样长，别拿 3 天比 14 天。
- 结算日要等窗口走完：次日留存要等窗口里最后一天来的人也过完第二天，7 日留存同理；要审核的平台从真的上线那天起算。
- 区间要能被打破：写「涨一点」不算下注；区间也不能包住「现在」，包住了就不是在赌它会变。拿不准就写宽一点，但要写出数。
- 前后对比先看来源：这几天有没有推广、大号转发、节假日，有就分开算，或者写「看不出」。
- 能做 A/B 的优先 A/B；每组要多少人看下面的表，人不够别急着看 p 值。结束时赢的那组写死进代码、删掉开关。
- 平台不给你自己的数据时，主指标只能从平台后台看得到的数里挑，让用户截图给你。
- 没中不是坏事，超出上沿也算没中（说明依据低估了）：追到错在哪条依据，把那条记忆降级或失效，这才是下注的用处。

## 怎么判：中 / 没中 / 看不出

别心算。主指标和护栏都换成比例（留存、转化、做完率；人均类的换成「至少做过一次的人占比」），跑同目录的 `settle.js`（只要 Node，不用装东西）：

```bash
node settle.js 200 1000 260 1000 23 28       # 发版前 200/1000，发版后 260/1000，预计 23%–28%
node settle.js 500 1000 480 1000 --guard 2   # 护栏：最多允许掉 2 个点
```

A/B 也一样：「前」填对照组，「后」填实验组。最后一行 `verdict` 照下表抄进卡的「结算」：

| 输出 | 卡上写 | 意思 |
| --- | --- | --- |
| `hit` | 中 | 落在预计区间里，而且变化不是噪声 |
| `miss` | 没中 | 整个 95% 区间都在预计区间外（超出上沿也算），或者往反方向变了 |
| `can't tell` | 看不出 | 分不出是不是噪声：结算日顺延，或者攒更多样本 |
| `not a bet` | 重写这张卡 | 预计区间包住了「现在」 |
| `held` / `broken` | 护栏守住 / 护栏破了 | 护栏用 `--guard` |

## 每组要多少人才看得出

想有 80% 的把握看出来（显著性 0.05），每组（发版前后各一段，或者 A/B 每组）大约要这么多人：

| 现在的值 | 差 2 个点 | 差 3 个点 | 差 5 个点 | 差 10 个点 |
| --- | --- | --- | --- | --- |
| 5% | 1,900 | 830 | 300 | 80 |
| 10% | 3,500 | 1,600 | 570 | 140 |
| 20% | 6,300 | 2,800 | 1,000 | 250 |
| 30% | 8,200 | 3,700 | 1,300 | 330 |
| 50% | 9,800 | 4,400 | 1,600 | 390 |

自己算：每组人数 ≈ 16 × p × (1 − p) ÷ 差²（p 和差都写成小数）。

一段窗口里的人比表里少的时候：

- 只赌大变化（预计差 10 个点上下），小改动就别下注了；
- 拉长窗口（两周、一个月），结算日跟着往后推；
- 结出「看不出」也有用：说明在现在的量级上，这类改动量不出效果，以后排优先级时把它当小改动。
