# 小游戏迭代：一圈怎么转

人定三件事：**北极星和边界**、**方案点不点头**、**真机好不好玩**。其余（调研、方案初稿、制作、量数、归因、记经验）AI 做。

冲突时：用户当轮说的 > 当版 PRD > 项目自己的规则和 skill > 本文件。本文件只管「这一步干什么、结果写到哪」；项目里有更具体的做法（发版脚本、宣发规范、清理清单）就交给它们，不复制。

## 项目里的四份东西

skill 只放方法；每个项目自己的状态放在项目仓库里，默认 `docs/loop/`（项目已经有放文档的地方就用已有的，在 `project.md` 里写清楚）：

| 文件 | 放什么 | 模板 |
| --- | --- | --- |
| `docs/loop/project.md` | 北极星、数据从哪看、上线平台和硬约束、PRD 放哪、每一步交给项目里哪个脚本 / 文档 | 本文件「第一次用」 |
| `docs/loop/bets.md` | 下注账本 | [bets.md](bets.md) |
| `docs/loop/memory.md` | 经验 | [memory.md](memory.md) |
| `docs/loop/versions/<版本>.md` | 每版 PRD | [prd-template.md](prd-template.md) |

## 第一次在一个项目里用（还没有 `docs/loop/`）

1. 先看仓库：怎么构建、发到哪些平台、有没有埋点 / 看板、有没有现成的 PRD 和发版脚本。
2. 一次问完四件事（仓库里看得出来的别问，写成「我看到的是 X，对吗」）：
   - 北极星：最多两个数，比如次日留存、分享带回来的新用户。之后每张下注卡的主指标只从这里挑。
   - 数据从哪看：自建看板 / 平台后台 / 第三方统计；哪些平台根本拿不到数。
   - 上线平台和硬约束：包体上限、最低系统 / 客户端版本、能不能联网、审核规则。
   - 发版、宣发、清理现在怎么做（有脚本 / 文档就记路径，没有就先空着）。
3. 照下面的样子建 `project.md`，从 [bets.md](bets.md) / [memory.md](memory.md) 抄「账本开头」建另外两份；给用户看一眼再提交。
4. 在项目的 `AGENTS.md` / `CLAUDE.md`（有哪个用哪个）加一行：「迭代和新游戏按 minigame-loop 走，项目状态在 `docs/loop/`」。

`project.md` 长这样：

```markdown
# <游戏名> · 迭代用的项目卡

- 北极星（<日期> 用户定）：① <指标>（<在哪看>）；② <指标>（<在哪看>）。做完率、报错这类当护栏。
- 数据从哪看：<看板地址，不带 key> / <平台后台哪一页>；拿不到数的平台：<…>。
  - 密钥（看板 key、后台账号）每次让用户当场给，只用来拉数：不写进任何文件、提交，也不在回复里复述。
- 平台和硬约束：<平台>：<包体上限 / 最低版本 / 联网 / 审核>；…
- PRD 放哪：`docs/loop/versions/`（或 <已有位置>）。
- 每一步交给谁：制作 <项目的开发规则 / skill>；发版 <脚本 / 文档>；宣发 <文档>；清理 <文档>。没有的写「无，按 minigame-loop 默认」。
```

## 每次开工先做

1. `git status`：不认识的改动停下问，别动别人的东西。
2. 读 `docs/loop/bets.md`：有到期没结算的下注 → 先结算（第 7 步），再开新的。
3. 在 `docs/loop/memory.md` 里找和这次有关的条目：「生效」的照做，「候选」的只当提示、不当结论。
4. 分清这次是哪种：**迭代**（改已有的游戏）→ 当版 PRD；**新游戏** → [new-game.md](new-game.md)。

## 用户说「开新版本 / 做下一版」时

1. 做完「每次开工先做」。
2. 对一遍上一版 PRD 的最后几步（发版 / 宣发 / 结算 / 沉淀）：没做完的列给用户，问先收尾还是带着开新版。
3. 调研：这版想做的东西先出参考对比图（第 1 步），用户点。
4. 一次问完开工要定的事：做哪几样、先后顺序、在哪个分支做（开分支要用户点头）、哪几样算大改动要下注。
5. 照 [prd-template.md](prd-template.md) 建本版 PRD；大改动在 `bets.md`「待发」里占好位。
6. 之后一步一验收（第 3 步）。

## 用户问「要不要做 X / 下一步做什么」时

1. X 预计动北极星里的哪个数？说不出来就先不做，或者当小改动做（不下注）。
2. 翻记忆里相关的条目，「失效」的也看：以前为什么不行。
3. 给建议，附一张下注卡草稿让用户点。

## 用户问「这版效果怎么样 / 复盘」时

1. 下过注的改动：按卡结算（第 7 步），只按卡上写好的口径说话。
2. 没下注的改动：可以拉数给用户看，但只写「这段时间 X 从 a 到 b」，不说是哪个改动的功劳——事后找原因谁都找得到。
3. 想以后说得清：下一版开工时给它补一张卡。

## 一圈九步

| # | 做什么 | 结果写到哪 | 用户要做的 |
| --- | --- | --- | --- |
| 1 | 调研：以图代言 | PRD §1 | 从候选图里点一张 |
| 2 | 方案：PRD；大改动加下注卡 | PRD、`bets.md` | 点头 / 改 |
| 3 | 制作：一步一验收 | PRD「步骤」 | 每步看一眼 |
| 4 | 质量验收 | PRD 验收节 | 真机上手 |
| 5 | 发版 | `project.md` 里写的发版做法 | 说「发」；平台上传 / 送审 |
| 6 | 宣发 | `project.md` 里写的宣发做法 | 自己发 |
| 7 | 结算：到期拉数对账 | `bets.md` | 给数据（当场给 key 或截图） |
| 8 | 沉淀：经验进记忆 | `memory.md` | 看一眼新条目 |
| 9 | 收尾清理 | `project.md` 里写的清理做法 | 拍板清单 |

### 1. 调研：以图代言

- 别让用户用文字描述玩法。先找 3–6 个真实参考（游戏截图、录屏帧、社区笔记截图），拼成一张对比图（拼不了就列图片路径 / 链接），每张配一句「它的核心操作是什么」，让用户点。
- 点中的那张提炼成三行写进 PRD §1：核心操作（一个动词）、一局怎么结束、靠什么让人再来一局。
- 参考只借思路：文字、素材、画面原样不拿；不碰别人的 IP。

### 2. 方案：PRD 的写法

- 每一段都要能直接变成开发动作（改哪个文件、加哪个参数、验收量什么）；变不成动作的话不写。
- 决定记录（PRD §0）：谁、什么时候、原话、定了什么；AI 自己定的标「AI 定（都能改回）」。
- 新功能和大改动（新玩法、改核心手感、改首页 / 主流程、改分享 / 积分 / 排行规则、新游戏上线）→ 开一张下注卡，和 PRD 一起给用户点。bug、文案、参数微调不用下注。

### 3. 制作：一步一验收

- 一步 = 一个用户看得见的变化。做完先自己验（类型检查 / 构建 / 测试 / 截图），再把证据给用户看，停下等点头，点头了才开下一步。
- 每步收尾同一轮更新 PRD 的「步骤」和 §0；用户改主意就记进 §0，不靠聊天记录。
- 手感、动效、声音这类，自动测试只能证明「对不对」，「好不好」只能真机上手：先出能摸的东西，再抠参数。

### 4. 质量验收

- 每个平台至少一台真机（两种系统都发就两种都试）；低端机和最低支持版本也开一次。
- 有包体上限的平台，每步记一次包体，快到线就停下。

### 5–6. 发版、宣发

- 照 `project.md` 写的做法来；部署、上传、发帖一律等用户开口。
- 每个推广渠道（每条笔记、每个群、每个合作方）带一个自己的来源参数，结算时才分得清是改动起的作用，还是推广带来的人。

### 7. 下注和结算（细则在 [bets.md](bets.md)）

- 下注 = 一次能被证伪的判断：主指标、现在多少、预计到多少（区间）、哪天结算、什么结果算判断错、依据（引用哪几条记忆）。
- 结算 = 到期按卡上的口径拉数、逐条对账，写「中 / 没中 / 看不出」和原因。没中就追到是哪条依据错了，那条记忆降级或失效。
- 数据不全（看板挂了、留存窗口没走完、样本不够）不下结论：写「看不出」并顺延。宁可不结，也不瞎结。
- 对外（宣传、合作、私信）只报口径里算得上的数。

### 8. 沉淀（细则在 [memory.md](memory.md)）

- 一条 = 结论 + 依据；不写过程流水，不写会过期的数字（数字留在 PRD 或结算记录里，记忆里写在哪）。
- 每条带作用域、证据等级（现象 / 机制 / 推断）、状态（候选 / 生效 / 失效）。

## 门禁：会话结束 ≠ 做完

每一步收尾前对一遍，缺哪样补哪样，补不了就明说：

- PRD §0 决定记录和「步骤」同一轮更新了；
- 大改动有下注卡；到期的卡结算了；
- 新经验进了 `memory.md`，或者明确说「这次没有新经验」；
- 验证真跑过，没跑的写清楚哪项没跑、为什么。

## 不做的

- 不搭多 Agent 框架、远程容器、任务队列：一个人 + 一个 AI 编程助手，当前会话就是调度。
- 不自动每天看数、不自动改线上：要的话等用户开口再加定时任务。
- 不把密钥、用户存档、平台没公开的资料写进仓库。
