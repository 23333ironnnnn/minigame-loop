# 记忆：规则和条目格式

规则在这里；条目在项目的 `docs/loop/memory.md`。

## 四类东西各放各的

1. 约束（红线）：`project.md` 的「平台和硬约束」、项目自己的开发规则、平台文档。不抄进记忆。
2. **经验：`memory.md`。**
3. 流程：本 skill 和项目自己的开发 / 发版文档。
4. 事件：PRD §0 决定记录、`bets.md` 账本。

## 写法

- 一条 = 结论 + 依据。不写过程，不写会过期的数字（数字留在 PRD / 结算记录里，这里写在哪）。
- 证据分三级：**现象**（看到过，不知道为什么）、**机制**（知道为什么：有代码、文档或规则原文）、**推断**（推出来的，没验过）。现象级和推断级的不许写「显著」「一定」「必然」。
- 新条目一律先是「候选」；被一次结算或第二次独立的事印证了，再改「生效」。被推翻 → 「失效」，写日期和原因，条目不删：以后有人想再试，先看它为什么失效。
- 作用域往窄了写：只在这个游戏验过就写这个游戏。别的项目的经验抄过来，一律从「候选」开始。
- 编号接着往下排，不复用。

```markdown
### M-<编号> <结论一句话>
- 作用域：<这个游戏 / 某个平台 / 所有游戏>
- 证据：现象 / 机制 / 推断 —— <依据：文件、PRD 条目、结算 B-编号、用户原话>
- 状态：候选 / 生效 / 失效（<日期> <原因>）
```

## 什么时候读、什么时候写

- 读：每次开工找相关条目；写下注卡「依据」时引用编号。
- 写：结算完（中了升级、没中降级）；踩坑并且定位到原因时；用户说「记一下」时。写完给用户看一眼。

## 账本开头（第一次用时抄进 `docs/loop/memory.md`）

```markdown
# 经验

规则：minigame-loop 的 memory.md。

## 条目

- （空）
```

真实条目长什么样：minigame-loop 仓库里的 `examples/kacha-bear.md`。
