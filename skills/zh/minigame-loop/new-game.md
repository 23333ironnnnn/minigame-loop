# 新游戏生产线

适用：开一款新的小游戏（新仓库，或者在已有项目里新开一个构建目标）。迭代已有的游戏不看这里。

## 立项卡（写进新 PRD §0，用户点头才开 spike）

- 一句话玩法：核心操作一个动词（「点一下就跳」「捏一下就变形」）。
- 参考图：调研那步用户点中的那张。
- 北极星和数据源：从 `project.md` 继承，或者这款单独定；平台拿不到自己的数据，就只挑后台看得到的。
- 边界：包体上限、最低系统 / 客户端版本、能不能联网、不碰别人的 IP。多线程、离屏画布、WASM 这类能力先查平台文档支不支持、从哪个版本起，并给不支持的版本留一条路。
- 和已有游戏的关系：共用存档 / 角色 / 账号吗？共用的话先定怎么读。
- 用户的事：平台上建应用拿 ID、要排行榜就在平台后台建榜、新构建目标点头。

## 顺序（每一步做完停下，等用户点头）

1. **spike**：只做核心操作 + 一关，量真机手感和包体。用户点头再往下。
2. **资产**：先列清单，再定风格锚点，然后批量做。
3. **关卡工厂**（有「关」的游戏）。
4. **结果卡 / 积分 / 排行**：一局结束给一张能晒的结果、一个能比的分。
5. **打包审计**：按平台规则自查（包体、禁用的接口、文案）；用户上传、双端真机。
6. **宣发 + 下注**：新游戏上线本身就是一张下注卡。

## 底座：固化层拿来用，可变层新写

摆法（同仓库新开构建目标，还是新仓库拷一份底座）spike 前问用户。

- 固化层（已有项目里验过的）：打包配置、平台适配（同一份代码按平台换实现）、存档读写、平台能力的桥（登录、分享、排行）、分享海报、公告。照写法另起一份，别直接改老游戏的。
- 可变层（新游戏自己写）：场景、操作、物理、关卡生成、结果卡内容、资产、文案。
- 第一款游戏没有固化层：做完第一款，把上面这几样整理成能直接拿来用的样子，就是下一款的底座。

## 关卡工厂（有「关」的游戏）

- 不一关一关手摆：每关 = 生成算法 + 参数 + 种子（seed），同一组输入永远生成同一关。
- 先回答两个问题再选做法：生成出来是不是一定能过？判定能不能过耗不耗时？一定能过 → 运行时按关号现生成；不一定 → 离线生成 + 判定，把过了的关写进包里。
- 难度曲线写成「参数随关号变化」的一张表放进 PRD，不散在代码的 if 里。
- 调试入口 `?debug&level=N&seed=S` 直接进某关，和玩家走同一条生成链路。
- 改了生成算法就逐关比对：同 seed 改前改后对一遍，只允许预期内的关变化。
- 玩家报某关有问题：拿到关号 + seed 就能原样复现。

## 资产

- 先列清单（角色 / 场景 / UI / 音效，每样用在哪）进 PRD，再动手做。
- 风格锚点：第一张用户点头的图，当后面所有图的参考，别每张重新描述风格。
- 音效按类分：背景音乐 / 交互（跳、落地、点击）/ 状态（过关、失败）/ UI。
- 素材原创或有授权（来源写进 `CREDITS`），不拿参考作品的原图、原音。
